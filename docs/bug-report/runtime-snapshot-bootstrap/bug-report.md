# 隔离配置触发 OpenCode 隐式联网安装

## 诊断胶囊

| 项 | 记录 |
|---|---|
| 现象 | 新建空 XDG config 后，OpenCode 启动阶段可能尝试补齐插件运行依赖，离线环境等待网络超时 |
| 根因 | 隔离目录存在但不完整，被 OpenCode 识别为需要 bootstrap 的可写全局配置 |
| 诊断策略 | 用真实 OpenCode 1.18.3 启动到 health/agent 探针，记录首次可用时间与网络相关日志 |
| 超时策略 | 禁用模型目录抓取和默认/外部插件；把空全局配置做成完整只读目录，启动仍受 15 秒上限 |
| 预警策略 | 真实版本契约测试要求在生产 deadline 内加载最终 agent 权限，不提交模型 prompt |
| 用户交互修正 | 离线或受限网络中能快速进入 Explore；启动失败会明确显示，不会长时间无进展 |

## Bug report

1. **报告人**：真实 OpenCode 契约探针超时分析发现。
2. **复现步骤**：为 OpenCode 指定全新的空 XDG config 并启动服务；旧行为会尝试运行依赖 bootstrap，约等待网络超时后才可用或失败。
3. **根因分析**：隔离配置目录的结构触发 OpenCode 包管理路径，单纯设置“禁用外部插件”不足以避开初始化检查。
4. **修复方案**：创建只读 `opencode` 全局配置目录和排除文件，同时设置离线模型/插件开关；继续保留同一 OS 用户原有 XDG data 认证路径，不复制凭据。
5. **验证方式**：真实 OpenCode 1.18.3 health/OpenAPI/agent/skill 探针约 1.5 秒完成，并由 serverRunner 全套回归清理服务进程。
